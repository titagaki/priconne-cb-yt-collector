# 09. スラッシュコマンド

実装先: `src/priconne_cb_collector/interface/commands.py`

判断の理由は [`docs/discussion/`](../discussion/README.md) を参照。

## 1. コマンド一覧

| コマンド | 権限 | 動作 |
|---|---|---|
| `/status` | 全員 | 収集中か待機中か、収集開始からの経過、今期間の収集件数、クォータ残量 |
| `/start` | 管理者 | **収集を即時開始する。唯一の起動手段。** 実行前に `bosses.yaml` の内容を Embed で提示し、確認ボタンを押させてから開始する |
| `/stop` | 管理者 | **収集を停止し待機状態へ戻す。唯一の終了手段。** 未投稿分を投げ切り、収集件数サマリを投稿する。DB のデータは消さない |
| `/reload` | 管理者 | `bosses.yaml` / `config.yaml` を再読込 |
| `/collect` | 管理者 | 手動で収集を1回実行（クォータ消費の確認ダイアログを出す）。**収集していないときは拒否する** |
| `/recent [boss]` | 全員 | 直近の収集結果を最大10件表示（未投稿含む） |

`/collect` を収集していないときに拒否するのは、`videos.cb_period` が NOT NULL だから
（[07](07-persistence.md) §1）。

## 2. `/start` の確認ステップ

`/start` は `bosses.yaml` の内容を Embed で提示し、確認ボタンを押させてから開始する。
このステップは省略しない。

**開始を知らせるのはこのコマンドの返信だけ。**承認後の返信に `cb_period` と開始時刻を含める。
ボス構成一覧は直前の確認 Embed に出ているので繰り返さない（[04](04-schedule.md) §3）。

収集の開始・終了は `/start` と `/stop` だけで決まる。日付による自動開始も自動終了も無い
（[04](04-schedule.md) §2）。**`/stop` するまで収集は止まらない。**

## 3. `/collect` の確認ステップ

`/collect` は毎回クォータを消費する（1 巡 = 100 ユニット）。実行前に、投げる OR クエリと
本日の消費量を Embed で提示し、確認ボタンを押させる。
