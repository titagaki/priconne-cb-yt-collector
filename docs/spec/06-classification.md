# 06. 判定ロジック

実装先: `src/classify/boss.py`, `src/classify/battle_type.py`, `src/classify/metadata.py`

判定はすべて **タイトル + 説明文（先頭500文字）** を対象に、正規化を行ってから実施する。

## 1. 正規化

1. 全角英数記号 → 半角（NFKC 正規化）
2. アルファベット → 小文字化
3. カタカナはそのまま（ひらがな化はしない）
4. 空白・記号（`【】[]()「」/|-・`）を区切りとして扱う

## 2. ボス判定

### 2.1 優先度A: ボス名マッチ

- `bosses.yaml` の `name` および `aliases` を正規化した文字列で部分一致検索
- 複数ボスにヒットした場合は**複数タグを許可する**（比較動画・まとめ動画があるため）。ただし 3 体以上ヒットした場合は「まとめ動画」として `is_summary = true` を立て、投稿先は専用スレッド（または通常チャンネル）にする
- ヒットしたボスの `index` と、マッチした文字列を `match_source` として記録する

### 2.2 優先度B: EX表記（要検討事項あり → [11-2](11-open-questions.md#11-2-ex表記を採用するか)）

EX表記を**検索クエリには使わない**。`ex1` 等での検索はノイズが多すぎるため、
**すでに他の経路で収集済みの動画に対する、補助的な分類手段としてのみ使う。**

適用条件（すべて満たす場合のみ）:

1. 優先度A（ボス名）でマッチしなかった
2. `config.classify.enable_ex_notation == true`
3. 本文中にプリコネ文脈語が含まれる（`プリコネ` / `クラバト` / `クランバトル` / `priconne`）
4. 動画の `publishedAt` が**稼働期間内（トレーニング開始以降）**（前後の月のEX表記を誤って今月のボスに割り当てないため）

マッチパターン（`N` は 1〜5）:

```
ex\s?N        →  ex1, EX 1, ex-1
Nボス         →  1ボス, 4ボス
ボスN         →  ボス3
第N[ボス弾]   →  第2ボス
[①-⑤]        →  丸数字
```

マッチしたら `boss.index == N` のボスに割り当て、`match_source = "ex_notation"` を記録する。

**衝突時のルール:** ボス名と EX番号の両方がヒットし、かつ食い違う場合は**ボス名を優先**し、WARN ログを出す。

**採用しない場合:** ボス名でマッチしない動画は `on_boss_unknown` の設定に従う。
実装は設定フラグで両対応にし、既定は `true`。

## 3. 通常 / 持ち越し 判定

出力は 3 値: `normal` / `carryover` / `unknown`

### 3.1 持ち越し判定パターン（優先）

```
持ち越し / 持越し / 持越 / もちこし
繰り越し / 繰越
(\d{1,2})\s?秒(持ち越し|持越|から|スタート|start)
持ち越し\s?(\d{1,2})\s?秒
```

- 数値がキャプチャできた場合は `carryover_seconds` に格納（1〜90 の範囲外は無効として捨てる）
- **`持ち` 単体はパターンに含めない**（「持ち込み」「気持ち」等の誤爆源）

### 3.2 通常判定パターン

```
通常 / 通常編成 / 通常凸
初手 / 初凸 / 素凸 / 1凸目
フルタイム / 90秒 / フル(?!オート)
```

### 3.3 判定順序

1. 持ち越しパターンにヒット → `carryover`
2. 通常パターンにヒット → `normal`
3. どちらもなし → `unknown`

**注意:** `フルオート` は「通常」ではなく別軸の属性（§4）。`フル(?!オート)` の否定先読みで取り違えを防ぐこと。
両方ヒットした場合は持ち越しを優先する（持ち越し動画で「通常時より〜」と説明文に書かれるケースがあるため）。

## 4. 付加メタデータの抽出（すべて任意項目、取れなくてよい）

| 項目 | パターン例 | 格納 |
|---|---|---|
| 段階 | `([1-5])\s?段階`, `段階\s?([1-5])` | `phase: int` |
| ダメージ | `(\d+(?:\.\d+)?)\s?(億\|万)`, `(\d{4,})万` | `damage: int`（万単位に正規化） |
| フルオート | `フルオート`, `full\s?auto`, `フルオ` | `is_full_auto: bool` |
| 手動 | `手動`, `マニュアル` | `is_manual: bool` |
| トレモ | `トレーニングモード`, `トレモ`, `練習モード`, `検証` | `is_training_footage: bool` |

抽出失敗は `null` とし、判定全体を失敗させないこと。

### トレモ動画の扱い

トレーニングモードでの撮影動画は本番と条件が異なる場合がある（周回状況による段階のズレ、持ち越し検証の不成立など）ため、**除外はせず、表示上区別できるようにする**。判定は以下の OR:

- タイトル/説明文が上記パターンにヒット → `training_evidence = "keyword"`
- または `discovered_phase == "training"`（トレーニング期間中に収集された動画） → `training_evidence = "phase_only"`

前者が優先。後者だけの場合は「トレモ期間に投稿された」という弱い根拠なので、Embed 上の表現を分けること（[08](08-discord-posting.md)）。

## 5. 除外フィルタ

以下に該当する動画は**保存はするが投稿しない**（`status = "filtered"` として理由付きで記録）:

- `duration` が `min_duration_seconds` 未満 / `max_duration_seconds` 超過
- 配信中・配信予定（`exclude_live: true` の場合）
- タイトルに `title_ng_words` を含む
- ボス判定が `unknown` かつ `on_boss_unknown == "skip"`
