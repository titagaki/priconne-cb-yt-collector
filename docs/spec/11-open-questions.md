# 11. 未確定事項（実装前に確認すること）

**ここにある項目は仮実装せず、運用者に質問して決めてから実装する。**
決定した項目は、決定内容を該当の仕様文書へ反映し、この文書の該当節に「✅ 決定: …」と追記する。

## 11-1. 稼働期間のオフセット値

確定済みの前提:

- クラバト本番 = **末日の5日前 〜 1日前**（例: 末日31日 → 26〜30日の5日間）
- トレーニングモード = **本番開始の3日前から**（例: 23日から）
- したがって Bot の稼働期間は 23〜30日の 8 日間

残る論点:

- 実際の開催日程は月ごとに前後するため、末日基準のオフセットが常に当たるとは限らない
- 対策として `manual` モードと `trigger` モード（`/start` 起点）を用意してある

**確認事項:** 既定を `offset`（日付で自動開始）と `trigger`（`/start` で手動開始）のどちらにするか。
毎月 `bosses.yaml` の更新という手作業が必ず発生する以上、**`trigger` を既定にした方が「ボス未設定のまま自動起動してしまう」事故が起きない**ため推奨。ただし `/start` を忘れると収集自体が始まらないので、`offset` の日付になっても `/start` されていない場合に催促を投稿する保険を入れるかどうかも合わせて決めたい。

## 11-2. EX表記を採用するか

**採用のメリット:** ボス名を書かずに「4ボス」等とだけ書く投稿者が一定数いるため、取りこぼしが減る。

**採用のリスク:**

- `ex1` 等は他ゲーム・他コンテンツでも使われ、単体では識別力がない
- 過去月の動画に付いた EX表記を今月のボスに誤って割り当てる
- 「1ボス」等の表記は、その月のボス構成を知らないと意味を持たない

**本仕様での折衷案:** 検索クエリには使わず、収集済み動画の分類にのみ使用。かつ「プリコネ文脈語を含む」「期間内投稿」を必須条件とする（[06](06-classification.md)）。

**確認事項:** この折衷案でよいか。運用してみてノイズが多ければ `enable_ex_notation: false` で切れるようにしてある。

## 11-3. 品質フィルタの要否

`videos.list` で再生数が 1ユニットで取れるため、「再生数 N 未満は投稿しない」といったフィルタが低コストで実装できる。
ただし投稿直後の動画は再生数がゼロに近く、**速報性と両立しない。**

**選択肢:**

- (a) フィルタなし（速報性優先）
- (b) 投稿を N 分遅延させて再生数で足切り
- (c) チャンネル登録者数でのホワイトリスト運用

**確認事項:** どれを採用するか。現仕様は (a) 相当で、除外は尺・NGワードのみ。

## 11-4. 期間終了後の扱い

期間終了時点で未投稿のキューが残っている場合、投げ切るか破棄するか。
現仕様では**投げ切る**前提だが、終了直前に大量に溜まると翌日まで投稿が続く可能性がある。

## 11-5. RSS 監視チャンネルの初期リスト

`config.yaml` の `channels` はサンプル値のみ。運用者が実際のチャンネル ID を設定する必要がある。
API 検索の結果から「よくヒットするチャンネル」を集計して提案する機能を付けるか（`/suggest_channels` コマンド）。
