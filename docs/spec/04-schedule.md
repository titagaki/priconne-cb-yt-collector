# 04. 収集期間

実装先: `src/priconne_cb_collector/domain/schedule.py`（期間の生成・判定の純粋関数）、
`src/priconne_cb_collector/services/lifecycle.py`（期間の解決・遷移）

判断の理由は [discussion/収集期間](../discussion/schedule.md)、
ゲーム側の日程は [game/クランバトル](../game/clan-battle.md#開催スケジュール) を参照。

## 1. 状態

Bot の状態は2値のみ。トレーニング期間と本番期間は区別しない。

| 状態 | 期間 | 挙動 |
|---|---|---|
| 収集中 | `/start` 〜 `/stop` | API 検索を回して投稿する |
| 待機中 | それ以外 | YouTube へ一切通信しない。ポーリングループも回さない |

## 2. 期間の決まり方

**日付の設定は無い。**収集は `/start` で始まり `/stop` で終わる。それ以外の起動経路も
終了条件も存在しない。

```
開始  = /start が実行された時刻
終了  = /stop が実行された時刻（事前には決まらない）
```

- **`/stop` するまで収集は終わらない。**月をまたいでも自動では止まらない
- `cb_period`（`"YYYY-MM"`）は **`/start` した時点の JST の月**。月をまたいでも
  開始月のキーのまま変わらず、1回のクラバトで収集したものが1つのキーに収まる
- 収集中に再度 `/start` することは想定しない（`/stop` してから `/start` する）

## 3. 挙動と遷移

- **待機中:** ポーリングループを停止する。YouTube への通信も DB の定期参照も行わない
- **`/start` 時:**
  - 確認ダイアログ（ボス構成一覧つき）を出し、承認されたら収集を開始する（[09](09-slash-commands.md)）
  - **開始を知らせるのは `/start` 自身の返信のみ。**開始時刻と `cb_period` を含める。
    ボス構成一覧は直前の確認ダイアログに出ているので繰り返さない
  - `bosses.yaml` の `month` が `cb_period` と一致するか検証する。**不一致なら収集を開始せず、
    Discord に「ボス構成が未更新」の警告を投稿して待機したままにする**
  - 一致していれば初回収集を実行する
  - `layout: per_boss_thread` の場合、このタイミングでボス別スレッドを作成する（[08](08-discord-posting.md)）
- **`/stop` 時:** 未投稿分を投げ切ってから終了通知（ボス別の収集件数サマリ）を投稿し、
  ポーリングを停止する。DB のデータは消さない
- **再起動時:** `period_state.is_open` から状態を復元し、収集中だった場合のみ再開する。
  **再開しても何も通知しない**（開始を知らせるのは `/start` の返信だけなので、
  通知済みフラグのような仕組みは持たない）。ボス別スレッドは実在を確認し、欠けていれば作り直す

`month` の検証は `cb_period` と比較する。現在の月とは比較しない
（月末に開始した収集が、日付が変わった瞬間に止まらないようにするため）。
