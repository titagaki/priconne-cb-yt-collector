# 03. 収集期間とコマンド

実装先: `src/priconne_cb_collector/store.py`（期間の記録）、
`src/priconne_cb_collector/bot.py`（ループとコマンド）

判断の理由は [discussion/収集期間](../discussion/schedule.md)、
ゲーム側の日程は [game/クランバトル](../game/clan-battle.md#開催スケジュール) を参照。

## 1. 状態

Bot の状態は2値のみ。トレーニング期間と本番期間は区別しない。

| 状態 | 期間 | 挙動 |
|---|---|---|
| 収集中 | `/start` 〜 `/stop` | API 検索を回して投稿する |
| 待機中 | それ以外 | YouTube へ一切通信しない。ポーリングループも回さない |

## 2. 期間の決まり方

**日付の設定は無い。**収集は `/start` で始まり `/stop` で終わる。それ以外の起動経路も
終了条件も存在しない。

```
開始  = /start が実行された時刻
終了  = /stop が実行された時刻（事前には決まらない）
```

- **`/stop` するまで収集は終わらない。**月をまたいでも自動では止まらない
- `cb_period`（`"YYYY-MM"`）は **`/start` した時点の JST の月**。月をまたいでも
  開始月のキーのまま変わらず、1回のクラバトで収集したものが1つのキーに収まる
- 収集中に再度 `/start` することは想定しない（`/stop` してから `/start` する）

## 3. 挙動と遷移

- **待機中:** ポーリングループを停止する。YouTube への通信も DB の定期参照も行わない
- **`/start` 時:** 確認ステップを経て収集を開始し、初回の検索をすぐ実行する（§4）
- **`/stop` 時:** ポーリングを停止し、ボス別の収集件数サマリを返す。DB のデータは消さない
- **再起動時:** `period_state.is_open` から状態を復元し、収集中だった場合のみ再開する。
  **再開しても何も通知しない**

### `bosses.yaml` の月チェック

**`bosses.yaml` の `month` が `cb_period` と一致しない限り収集しない。**先月の構成のまま
回すと、当月と関係ないボス名で検索し続けることになるため。不一致のあいだは検索を投げず、
警告をログに残す。

検証は `cb_period` と比較する。現在の月とは比較しない
（月末に開始した収集が、日付が変わった瞬間に止まらないようにするため）。

## 4. スラッシュコマンド

| コマンド | 権限 | 内容 |
|---|---|---|
| `/start` | 管理者 | **収集を開始する。唯一の起動手段。** 実行前に `bosses.yaml` の内容を提示し、確認ボタンを押させる |
| `/stop` | 管理者 | 収集を停止し、ボス別の件数サマリを返す |
| `/status` | 全員 | 収集中かどうか、開始時刻、投稿済み件数を返す |

### `/start` の確認ステップ

`/start` は `bosses.yaml` の内容（対象月・5体のボス名とエイリアス）を提示し、
確認ボタンを押させてから開始する。**このステップは省略しない。**

**開始を知らせるのはこのコマンドの返信だけ。**承認後の返信に `cb_period` と開始時刻を含める。
ボス構成一覧は直前の確認メッセージに出ているので繰り返さない。

収集の開始・終了は `/start` と `/stop` だけで決まる。日付による自動開始も自動終了も無い。
