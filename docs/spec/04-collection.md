# 04. 取得と投稿

実装先: `src/priconne_cb_collector/youtube.py`（API）、
`src/priconne_cb_collector/classify.py`（判定）、
`src/priconne_cb_collector/bot.py`（巡回と投稿）

判断の理由は [discussion/動画の取得](../discussion/collection.md)、
[discussion/Discord 投稿](../discussion/posting.md) を参照。

1巡でやることは4つだけ。

```
1. ボス名の OR クエリで search.list を1回投げる
2. すでに投稿済みの video_id を除く
3. タイトルに NG ワードを含むものを除く
4. 残りをボスのチャンネルへ投稿し、成功したものを記録する
```

## 1. 検索

取得経路は **Data API v3 の `search.list` 1 本のみ**。`videos.list` は呼ばない。

`search_interval_minutes`（既定 30 分）間隔で 1 回だけ実行する。

```
GET https://www.googleapis.com/youtube/v3/search
  key, part=snippet, type=video, order=date, maxResults=50,
  regionCode=JP, relevanceLanguage=ja,
  publishedAfter={収集開始 - search_lookback_days},
  q="{ボス1} OR {ボス2} OR {ボス3} OR {ボス4} OR {ボス5}"
```

- **`bosses.yaml` の全ボス名を 1 つの OR クエリにまとめる。**`search.list` は結果件数に
  かかわらず 1 回 100 ユニット固定なので、1 巡 = 100 ユニットになる
- **クエリはボス名のみ。**「プリコネ」「クラバト」を足さない（対象にはこれらを含まない
  タイトルが多いため）
- エイリアスは検索クエリに使わない。エイリアスは §2 のボス判定にのみ使う
- `maxResults=50` の枠を全ボスで共有するため、1 巡で 50 件を超える新着があると取りこぼす
- 検索が失敗しても収集ジョブは落とさない。次の巡回で拾い直す

### クォータ

| API | 1回あたりの消費 |
|---|---|
| `search.list` | 100（結果件数によらず固定） |

```
100ユニット × 48巡/日 = 4,800（1日の上限 10,000）
```

**上限の半分以下に収まるので、消費量を記録する仕組みは持たない。**間隔を
`search_interval_minutes` で狭める場合のみ再計算すること（15分なら 9,600 で上限間際）。

**検索が唯一の取得経路なので、`YOUTUBE_API_KEY` は必須。**未設定なら起動を中止する。

## 2. 投稿先の決定

**判定するのは「どのボスか」だけ。**それ以外は何も抽出しない。

判定対象は**タイトルのみ**（説明文は見ない）。次の順で正規化する。

1. 全角英数記号 → 半角（NFKC 正規化）
2. アルファベット → 小文字化
3. カタカナはそのまま（ひらがな化はしない）
4. 記号（`【】[]()「」/|-・`）を空白に置き換える

正規化した文字列に対し、`bosses.yaml` の `name` および `aliases` で部分一致検索する。

- **`aliases` は `name` を置き換えるのではなく補う**（`aliases` を書いても `name` は常に候補に残る）
- **ちょうど1体にヒットしたときだけ、そのボスのチャンネルへ投稿する**
- **0体または2体以上にヒットした場合は判定不能**とし、`fallback_channel_id` へ投稿する

EX表記（`ex1` / `3ボス` 等）、通常 / 持ち越し、ダメージ、フルオート、トレモは
**判定しない**。投稿先が変わらないため。

## 3. NG ワード

タイトルに `title_ng_words` のいずれかを含む動画は**投稿しない**。正規化はせず、
生のタイトルへの単純な部分一致で判定する。

除外した動画は記録しないので、次の巡回でも検索結果には現れる（毎回同じ判定になるだけ）。

**尺・配信中かどうかでは除外しない。**それらの判定には `videos.list` の追加呼び出しが
必要で、混ざったら目で飛ばせば済むため。

## 4. 投稿

- 投稿先は運用者が**あらかじめ作成した既存チャンネル**。**Bot はチャンネルもスレッドも作らない**
- 投稿内容は**タイトルと URL の2行のみ**。Embed は組み立てない（URL を貼れば Discord が
  自動でカードを展開する）。**動画の説明文は転載しない**
- 投稿は直列化し、`post_interval_seconds` 間隔を空ける
- 429 を受けたら `Retry-After` に従って待機して再送する（**同一動画につき最大3回**）
- **投稿に成功したものだけを DB に記録する。**失敗した動画は記録しないので、次の巡回で
  再び見つかり自然に再試行される（[02](02-architecture.md) §3）
