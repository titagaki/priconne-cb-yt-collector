# 10. 非機能要件

## 1. エラーハンドリング

- **1件の動画の判定失敗が収集ジョブ全体を落とさないこと。** 個別に try/except し、`status = "error"` で記録して次へ進む
- YouTube API のエラーは指数バックオフでリトライ（最大3回、初回 2秒）
- `quotaExceeded` エラーはリトライせず、その日の検索を打ち切る（Bot 自体は停止しない）
- Discord への接続断は discord.py の再接続に任せる。投稿キューは保持する

## 2. ログ

- 構造化ログ（JSON Lines）でファイル出力
- 各動画について「収集元 / 判定結果 / 判定根拠となったマッチ文字列 / 投稿可否」を INFO で残す。**判定チューニングにログを使うため、マッチ文字列の記録は必須**
- クォータ消費は API 呼び出しごとに DEBUG、**その日の累計を INFO**（`quota daily total: date=... used=... limit=...`）。
  累計は収集ラウンドでクォータを消費したときに出す（消費ゼロのラウンドでは出さない）

## 3. テスト

必須のユニットテスト:

| 対象 | ケース |
|---|---|
| `domain/schedule.py`<br>`services/lifecycle.py` | 収集する/しないの境界（開始の前後1秒）、`cb_period` の決まり方（JST の月・月またぎで変わらないこと）、`/start` → `/stop` の往復、再起動時の復元 |
| `domain/classify/boss.py` | 名前一致、エイリアス一致、複数ヒット、EX表記、名前とEXの衝突、正規化（全角/半角/大小文字） |
| `domain/classify/battle_type.py` | 持ち越し各表記、秒数抽出、`フル` と `フルオート` の切り分け、判定不能ケース |
| `domain/classify/metadata.py` | トレモ判定（キーワード由来と期間由来の区別） |
| `adapters/sqlite_store.py` | 重複 INSERT が既存レコードを壊さないこと、開始 / 終了通知フラグが二重投稿を防ぐこと |

判定系のテストは、**実際の動画タイトルを模したサンプルを 30 件以上用意した表形式のテストケース**として書くこと。

`tests/` は実装と同じ層構造に分ける（[02](02-architecture.md) §3）。
