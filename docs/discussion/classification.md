# 判定ロジックの判断

対象となる表記の実態は [動画の表記慣習](../game/video-conventions.md) を参照。

## EX表記の採否

**採用したが、用途を分類のみに限定した。**

採用のメリットは明快で、ボス名を書かずに「4ボス」等とだけ書く投稿者が一定数いるため、
取りこぼしが減る。一方リスクが3つあった。

| リスク | 対策 |
|---|---|
| `ex1` 等は他ゲームでも使われ、単体では識別力がない | プリコネ文脈語（`プリコネ` / `クラバト` / `クランバトル` / `priconne`）の同時出現を必須にした |
| 過去月の EX表記を今月のボスに誤って割り当てる | 動画の `publishedAt` が収集期間内であることを必須にした |
| ボス構成を知らないと「1ボス」に意味がない | `bosses.yaml` の index と突き合わせる前提なので、構成が正しければ問題にならない |

### 検索クエリに使わない理由

`ex1` で YouTube を検索すると**ノイズが支配的になる。** 他ゲームのEXステージ、無関係な連番など、
プリコネ以外の動画が大量に返る。100ユニット/回を払ってノイズを取りに行く価値がない。

これは「取りこぼすくらいなら関係ない動画が混ざってよい」（[スコープと方針](scope.md#取りこぼすくらいなら関係ない動画が混ざってよい)）
と衝突しない。あちらは**判定に迷ったときの倒し方**の話で、こちらは**限られたクォータを何に使うか**という
配分の話。ヒット率の低いクエリに1回100ユニットを払うと、その分だけ他の検索ができなくなり、
かえって取りこぼしが増える。

**すでに他経路で収集済みの動画に対する補助的な分類手段**としてのみ使うことで、
文脈語チェックと期間チェックを効かせられる。検索では絞り込めない条件をあとから適用できる。

### 衝突時にボス名を優先する理由

ボス名と EX番号の両方がヒットし、かつ食い違う場合はボス名を採る。

ボス名は `bosses.yaml` で運用者が明示した文字列であり、EX表記は番号からの推定にすぎない。
根拠の強さが違う。ただし食い違い自体がエイリアス設定の誤りを示唆するので、WARN ログを残す。

## 実データによる検証（2026-07-26）

[2026年7月にボス名で検索した実データ](../reference/priconne_cb_2026-07_full.html)（126件、
無関係な動画を含む）に判定器を通し、3つの欠陥を見つけて直した。

### 1. `name` が `aliases` に上書きされていた

`bosses.yaml` が `name: "デミ・カリド"` / `aliases: ["デミカリド"]` の場合、
実装は `aliases` だけを見ており、**`name` そのものが一切マッチしなかった。**
タイトルは「デミ・カリド」と中黒つきで書かれるため、2ボスの動画を全件取りこぼしていた。

仕様（[06](../spec/06-classification.md) §2.1）は「`name` および `aliases`」と書いてあり、
実装が仕様に届いていなかった。`aliases` は `name` を補うもので、置き換えるものではない。

### 2. 秒数の単位が `s` だった

実データの秒数表記は **`s` が21件、`秒` が1件**。実装は `秒` しか見ていなかったため、
持ち越し動画22件のうち正しく判定できたのは1件だけだった。

さらに「4段階 オルレオン 11145万 34s」のように**持ち越し語を伴わず秒数だけ**書く形が
4件あり、これは型すら `unknown` になっていた。フルタイムが90秒である以上、
それより短い秒数の単独表記は持ち越しを意味する。素の `Ns`（1〜89）も根拠として採ることにした。

`90` を除外したのは、`90s` 単独はフルタイム＝通常と読むほうが自然なため。
「90秒持ち越し」のように語がある場合は従来どおり持ち越しになる。

修正後は**22件すべて正解、無関係69件での誤判定はゼロ**。

### 3. 「繰り越し」は使われていなかった

パターンに `繰り越し` / `繰越` を入れていたが、このゲームでは使われない表記だった。
誤爆源にしかならないので削除した。

## 正規表現の落とし穴

実装中に踏んだもの。いずれも回帰テストがある。

### `持ち` 単体をパターンに含めない

「持ち込み」「気持ち」など無関係な語に頻出する。「持ち越し」「持越」など、
**越の字を含む形でのみ**マッチさせる。

### 否定先読みは `(?!オート)` ではなく `(?!オ)`

通常編成の判定に `フル` を使うが、そのままだと「フルオート」にマッチしてしまう。
最初 `フル(?!オート)` としたが、これでは略記の **`フルオ`** に `フル` が一致し、
フルオート動画を「通常」と誤判定した。

`フル(?!オ)` にすることで `フルオ` / `フルオート` の両方を除外できる。

### 持ち越しと通常が両方ヒットしたら持ち越しを優先

持ち越し動画の説明文に「通常時より〜」のような比較が書かれることがある。
持ち越しは明示的に書かれる情報なので、こちらを信頼する。

## 扱わないと決めた項目

### ボスの「段階」

**2026-07-26 に削除した。**

当初はタイトルから段階（1〜5）を抽出し、Embed に「4段階」と表示していた。削除の理由:

- **トレーニングモードでは全段階を自由に見られる**（[クランバトル](../game/clan-battle.md#段階)）。「この動画は4段階目向け」という情報は、視聴者が段階を選べる以上そこまで重要ではない
- 段階はクランの周回進行に紐づく値で、**Bot の収集動作とは無関係**
- 実装上も抽出 → 保存 → Embed 表示で終わっており、絞り込みにも集計にも使っていなかった
- タイトルに段階が書いてあれば、Embed のタイトル（動画タイトルそのまま）にも出る。**情報が二重になっていた**

### 編成内容（キャラ構成）

表記揺れが激しく、誤った編成情報を出すくらいなら動画そのものを見てもらう方が確実
（[スコープと方針](scope.md#やらないこと)）。

## トレモ動画を除外せず区別だけする理由

トレモ撮影の動画は本番と条件が異なる場合がある（持ち越し検証が本番どおりに再現できないなど）。
ただし**編成の参考としては十分に有用**なので、除外せずバッジで区別することにした。

判定根拠は**タイトル/説明文のキーワードのみ**。当初は「トレモ期間中に収集した」ことも
弱い根拠（`training_evidence = "phase_only"`）として扱い、Embed の表現を分けていたが、
期間の区別自体を廃止したため成立しなくなった（[収集期間](schedule.md#状態を収集する--しないの2値にした理由)）。

結果的にこれで良かった。「トレモ期間に投稿された」は動画の内容について何も語っておらず、
根拠として弱すぎた。

## 複数ボスヒットの扱い

比較動画・まとめ動画があるため、複数ボスへのタグ付けを許可している。

ただし**3体以上ヒットした場合は「まとめ動画」**として扱い、ボス別スレッドではなく親チャンネルへ投稿する
（[Discord 投稿](posting.md)）。5つのスレッド全部に同じ動画が流れると、
どのスレッドを見ても同じものが目に入って邪魔になるため。
