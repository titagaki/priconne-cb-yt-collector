# スコープと方針

## 取りこぼすくらいなら、関係ない動画が混ざってよい

判定に迷う実装は**投稿する側へ倒す**。

クラバトは期間限定で、**その場で見逃した動画は後から取り返せない。** 初日にどの編成が通るかの
情報価値が最も高く、そこで1本取りこぼすと、必要だったかもしれない情報が永久に届かない。

対して、関係ない動画が混ざった場合の損害は「利用者が1本スキップする」だけで済む。
タイトルを見れば無関係だと分かるので、判断コストもほぼゼロ。**回復可能な失敗**にとどまる。

この非対称性から、`classify.on_boss_unknown` の既定は `post_as_unknown`
（ボス判定できなくても親チャンネルへ投稿する）とした。判定できなかったことを理由に
捨てるのではなく、人間に見せて判断してもらう。

> **注意:** これは「判定に迷ったとき」の倒し方であって、明確に不要と分かるものまで通す意味ではない。
> 尺・NGワード・配信中の除外フィルタは、迷いのないケースを落とすためのものなので引き続き適用する。

## ボス構成を自動取得しない

毎月のボス構成は運用者が `bosses.yaml` に手で書く。

自動取得の候補は公式サイトのスクレイピングだが、

- ページ構造の変更で無言で壊れる
- 壊れた場合、**前月のボス名で検索し続ける**という最悪の失敗をする
- 月1回・5行の手作業を自動化するために、壊れ方の悪い依存を増やす価値がない

判定ロジックの唯一の正を `bosses.yaml` に集約することで、判定がおかしいときに見る場所が
1ファイルに固定されるという副次的な利点もある。

エイリアスの揺れ（[表記慣習](../game/video-conventions.md)）は網羅できないため、
運用しながらログを見て運用者が追記する前提にした。**実装者が推測でエイリアスを足さない**のは、
足した本人以外に根拠が追えなくなるため。

## やらないこと

| 項目 | 理由 |
|---|---|
| 動画のダウンロード・再エンコード | 権利上の問題があり、Bot の目的（見つけて知らせる）に不要 |
| 動画内容の解析（サムネイル画像認識、字幕解析） | コストが判定精度の改善に見合わない。タイトルと説明文で十分な情報が得られる |
| YouTube 以外のソース（ニコニコ、Twitter/X） | クラバト攻略動画の主要な投稿先が YouTube に集中している |
| 編成内容（キャラ構成）の抽出 | 表記揺れが激しく、誤った編成情報を出すくらいなら動画を見てもらう方が確実 |
